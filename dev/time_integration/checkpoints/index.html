Checkpoints

A run on a shared cluster can be stopped at any time (preemption by a job of higher priority, the time limit of the partition). checkpoint_state takes the state of a run at the end of a step as plain host arrays, and restore_checkpoint! puts it back into the same run rebuilt from its configuration: the next step continues the run that wrote the checkpoint bit for bit (on the same backend and device model; a GPU of another model may round differently). Writing the file, how often, and resuming the time loop are the driver's business (HyperCloud's solve_equation with a Checkpointing); this package only defines what the state is.

What is saved and what is rebuilt

A step starts from the states and the particle set and recomputes everything else, so that is what a checkpoint holds:

savedwhy
rhos, the block state (blocks, block-major, all blocks)the solution
positions in memory order, N, N_interior, N_ghostmovers, adaptivity and the sweep of moving pieces change the particle set and its order
volumesre-estimated, remapped (content form, adaptivity, sweeps): not recomputable from the positions alone
is_boundary, tags, normals, wall_distances, wall_curvatureschange with the particle set (inserted, removed and swept particles, ghosts of moving pieces)
particle_ordersthe orders of the last step (a step resets them at its start; kept so the restored grid is the grid at the end of the step)
boundary_time, sweep_timethe time the moving pieces' ghosts and the swept region belong to (_sync_boundaries! compares them with the step's time)
the neighbour lists: counts, indices, weights, distances (per particle in slot order, whatever the slot layout)derived, but not reproducible across devices: a run's grid is built and searched on the host and then stepped on a GPU, an adaptivity event searches a host copy, and a GPU's exp rounds differently from the host's (a restore that searched again on the GPU was 1e-13 off the run that went through)

Rebuilt on restore: the cell list (a search over the restored positions, without wrapping them into the periodic box again, whose lists are then replaced by the saved ones in the grid's slot layout), and through geometry_version every cache derived from the lists (the MLS moment matrices, the slot weights, the ghost geometry of the block pipeline). The stepper's stage buffers and MOOD masks are set at the start of every step and are not part of the state. The checkpoint also records D, M, the float type, the support radius and the spacing: a checkpoint of another kind of run is refused.

The per-particle sums run in a fixed order (every particle sums over its own slots), the neighbour search sorts the particles of every bin, and the partial sums of a split block state are added on the host in block order, which is why a restart is exact rather than close.

Usage

ck = checkpoint_state(pg)                 # or checkpoint_state(pg, bs), checkpoint_state(devs)
# ... save `ck` (a NamedTuple of Vectors and numbers) with JLD2 or Serialization; the run is stopped ...
# ... later: build the run from the same configuration as before ...
restore_checkpoint!(pg, ck)               # or restore_checkpoint!(pg, bs, ck), restore_checkpoint!(devs, ck)

A split block state (BlockDevices) is saved as one block state (the grid of its first part, every part holds the same cloud, and the blocks of all parts), so a checkpoint moves between a single block state and splits over any number of parts.

HyperCloudCore.checkpoint_state — Function
checkpoint_state(pg::ParticleGrid) -> NamedTuple
checkpoint_state(pg::ParticleGrid, bs::BlockState) -> NamedTuple
checkpoint_state(devs::BlockDevices) -> NamedTuple

The state of a run at the end of a step, as host arrays (copies, device grids included), to restore with restore_checkpoint! into the same run rebuilt from its configuration:

  • the particle set: positions (in memory order), volumes, is_boundary, tags, particle_orders, normals, wall_distances, wall_curvatures and the counts N, N_interior, N_ghost;
  • boundary_time and sweep_time (the time the moving pieces' ghosts and the swept region belong to);
  • the neighbour lists: neighbor_counts (per particle) and neighbor_indices, neighbor_weights, neighbor_distances (particle by particle, in slot order; independent of the grid's slot layout);
  • the states: rhos, and for a block state blocks (the block-major array of all blocks, nb N entries) with nb;
  • for the consistency check of the restore: format, D, M, T (the float type's name), R and dx.

The neighbour lists are saved although a search would find them again: their weights are not reproducible across devices (a run's grid is built and searched on the host, then stepped on a GPU whose exp rounds differently). The caches derived from the geometry are not part of it (the restore makes them stale). A split block state (BlockDevices) is saved as one block state: the grid of the first part (every part holds the same cloud) and the blocks of all parts (host_state). Plain data only (Vectors of static vectors, numbers, strings), for any file format (JLD2, Serialization).

HyperCloudCore.restore_checkpoint! — Function
restore_checkpoint!(pg::ParticleGrid, ck) -> pg
restore_checkpoint!(pg::ParticleGrid, bs::BlockState, ck) -> pg
restore_checkpoint!(devs::BlockDevices, ck) -> devs

Puts the state of a checkpoint_state back into a run built from the same configuration (the same equation, grid parameters, scheme and stepper; the initial conditions may be set or not, they are overwritten): the particle set and the states are copied (the grid grows if the checkpoint holds more particles), the cell list is rebuilt by a search over the restored positions without wrapping them again (pg.neighbor(pg; wrap = false)), and the neighbour lists are then replaced by the saved ones, in the grid's slot layout; every geometry cache is stale afterwards. The next step then continues the run that wrote the checkpoint bit for bit (same backend and device model).

A split block state takes a checkpoint of any split or of a single block state (the blocks are distributed by the parts' block ranges) and vice versa. Throws an ArgumentError if the checkpoint belongs to another kind of run: another format, dimension, state length, float type, support radius or spacing, or a block state for a grid alone (or the other way round).
