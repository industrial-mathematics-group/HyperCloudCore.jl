## Findings

### F1 (medium, CONFIRMED) — #40's accuracy claims and its 2-D quadrature test rest on a harmonic test function; for a generic f the 2-D box orders are 2, not 3-4, and Shepard is 25-50× worse than stated
`test/unit_schemes.jl:917-923`, `docs/src/particle_grids/volumes.md:16,18`, `src/Grid/Volumes.jl:31-33,48,74-75`,
and the commit message. The 2-D test and the documented numbers use f = exp(x) cos(y). That function is harmonic
(Δf = 0), so the leading h² term of the lattice midpoint rule, which is proportional to ∫Δf, vanishes. The
first-order wall terms of Shepard nearly cancel too (relative +0.082 h from exp, −0.084 h from cos). `vol_new.out`,
unit box, R = 2.5h, relative error of Σ_int V f at N = 20/40/80:

| estimator | f = exp(x)cos(y) (test) | f = exp(x+y) | f = x² + y |
|:--|:--|:--|:--|
| Shepard | 1.6e-4 / 7.8e-5 / 3.8e-5 | **8.7e-3 / 4.4e-3 / 2.2e-3** | 1.1e-2 / 5.3e-3 / 2.6e-3 |
| MLS0 | 9.7e-7 / 1.8e-7 / 2.6e-8 | 6.3e-4 / 1.5e-4 / 3.8e-5 (order 2) | 7.5e-4 / 1.9e-4 / 4.6e-5 |
| MLS1 | 2.3e-5 / 3.1e-6 / 4.1e-7 | **3.0e-3 / 7.9e-4 / 2.0e-4 (order 2)** | 3.6e-3 / 9.5e-4 / 2.4e-4 |
| MLS2 | 8.0e-7 / 5.4e-8 / 3.5e-9 | 5.1e-5 / 1.3e-5 / 3.3e-6 (order 2) | 6.2e-5 / 1.6e-5 / 3.9e-6 |

So "orders 3-4 in 2-D" is wrong: every MLS degree is second order on a box, the same lattice-midpoint limit as in 1-D.
"Shepard 2e-4 in 2-D at N = 40" is 4.4e-3, i.e. about 0.18 h relative. The 1-D claim "2e-3 at N = 40" is also too
optimistic: 5.5e-2 for x² and 8.6e-3 for exp(x) (relative, lattice). The test bounds `< 5e-4` (Shepard) and `< 1e-4`
(MLS1) pass only because of the special function: `t40.jl` gives 8.7e-3 and 3.0e-3 for exp(x+y), which would fail
both. The test therefore cannot detect a regression of the near-wall quadrature whose leading term is proportional
to ∫Δf, which is exactly the midpoint/one-sided error it claims to check. The code itself is right: interior volumes
sum to |Ω|, and compared with the parent this is a large improvement (Shepard 0.43 → 8.7e-3 for exp(x+y) at N = 20).
It also turns out that MLS1 is 4-5× less accurate than MLS0 on the box, which the docs table does not suggest.

- Fix: use a non-harmonic f in the test (exp(x+y)), with bounds of about 1.2e-2 (Shepard), 4e-3 (MLS1) and 1e-4
  (MLS2), and an order check MLS2 N = 20 → 40 (ratio < 0.3). Correct the docs table, the volumes text, the
  `ShepardVolumes`/`MLSVolumes` docstrings and the Volumes.jl header to "order 2 in 1-D and 2-D for every P (the
  lattice midpoint rule); Shepard first order, about 0.2 h relative on a box". Fix the test comments ("Shepard:
  1.6e-4", "2.3e-5") the same way.

### F2 (low, CONFIRMED) — #39 gathers every ghost: up to +22 % per step, and a third of those gradients are never read
`TimeSteppers.jl:335-336`. The pass now runs `update_content!` (fit plus limiter) on all ghosts. In 3-D the ghost
band is 40-60 % of the particles at moderate N. `cost.out` (lock, `-t 8`, OutflowBC box, fbb54d1 → a56944c, ms/step):
2-D N = 160 MUSCL3 3.67 → 4.05 (+10 %), 2-D N = 80 MUSCL5 3.00 → 3.16 (+5 %), 3-D N = 20 MUSCL3 9.27 → 9.58 (+3 %),
3-D N = 32 MUSCL3 38.0 → 39.7 (+4 %), **3-D N = 16 MUSCL5 29.2 → 35.6 (+22 %)**. 2-D N = 80 MUSCL3 is within noise.
`used.out`: 34-37 % of the ghosts are no neighbour of any interior particle (corner and edge regions, the outer band),
so their gradients are never read by a flux. Neither the commit nor the docs mention the cost. CLAUDE.md does not
require a cost statement, but the `time_stepper.md` step now says "every particle".

- Fix: gather only interior particles plus ghosts with at least one interior neighbour. Compute a mask once per
  neighbour search (a kernel over the interior slots, or a flag computed in `prepare_geometry!`), and pass it where
  the `is_boundary` test used to be (the argument count stays at 9). Or state the cost in the docs.

### F3 (low, CONFIRMED) — #39 also changes MOOD at walls (MOODu2 now sees ghost curvatures; starved ghosts lower EPD1 edges), undocumented and untested
`MOOD.jl:256-266`. `MOODu2` compares the curvature of a particle with the cached curvatures of its neighbours. Ghost
gradients used to be zero, so near a wall `minAbs = 0` and the ratio test always failed. MOODu2 was therefore MOODu1
on the first rows. `mood_{old,new}.out` (lattice channel, MUSCL3, N = 80, t = 0.5):

| criterion, condition | before: err, drops/step near the wall | after |
|:--|:--|:--|
| u1 1e-3, Mirror2 | 2.66e-2, 0.2 | 1.04e-2, 0.0 |
| u2 1e-3, Mirror2 | 2.66e-2, 0.2 (= u1) | 1.03e-2, 0.0 |
| u2 1e-4, Mirror2 | **7.43e-2, 5.8** | 1.03e-2, 0.0 |
| u2 1e-4, exact | 1.41e-2, 0.8 | 8.7e-3, 0.0 |

This is an improvement, but it changes MOOD decisions next to every wall for every MOODu2 run, and neither the
commit nor `mood.md` mentions it. A second, smaller interaction: `update_content!` now writes starved orders of ghosts
(`MUSCL.jl:365`). With the default `EPD1` (edge minimum) the interior side of an edge to such a ghost runs at the
ghost's order. `starve.out` shows this only for 1-D MUSCL5 with R = 2.5h (2 adjacent ghosts at order 3/4). It is
still better than before, when the ghost side was constant. The commit's statement "ghost orders never change" holds
within a step (they are only lowered in the full pass, before any partial pass), so the partial passes are correct.

- Fix: add a sentence to `mood.md` (u2) and `boundary_conditions.md` that ghosts carry gradients, curvatures and
  possibly lowered orders, and that MOODu2 near walls behaved like MOODu1 up to this change. Add a small test: the
  wall Gaussian with `MOODu2(1e-4)` and Mirror2 at N = 40 has no drops on the wall rows (it had 4.2/step before).

### F4 (low, CONFIRMED) — #40 silently changes `conservation_defect` next to walls
`Conservation.jl:39`. The face vector of a ghost is `S_ji = 2 V_j c_ji`, which is now 0. Every interior–ghost pair
therefore counts as a full defect (|S_ij + 0|), while the ghosts' own slots drop out of the sums. `cdef.out`
(bounded 20² lattice, MUSCL3): the largest near-wall particle defect goes 0.27 → **0.66**, and total.rel goes 0.45 →
0.17. Deep interior particles stay at 6e-15 on both trees. A flux across the wall is a boundary flux, not a pair
defect, so neither the old nor the new number means much, but the docstring says nothing about ghosts, and the
values of an existing diagnostic changed without notice. Simulations' `ConservationDefect` statistics do not call
it (they use their own exact boundary flux), so no stored result is affected.

- Fix: skip slots whose partner is a boundary particle (and the ghost rows) in the pair statistics, or report them
  as a separate `wall` group. Document either choice in the docstring.

## Accuracy and behaviour, other conditions (#39)

- **FixedDirichlet / OutflowBC / ExtrapolationBC.** Where the flux is upwind and the ghost is downstream, the
  ghost gradient is never read, and the results are unchanged (1-D advection; the 2-D OutflowBC box at 4 digits).
  Tangential to a wall, OutflowBC improves a lot (channel 0.057 → 8.9e-3 at N = 160). The 2-D ExtrapolationBC(2) box,
  which blew up before, is now stable (2.05e-1/4.3e-2). Inflow steps barely change (overshoot −3 %). A constant
  Dirichlet band has a zero gradient, so its result only changes where the band meets the interior. The commit's "any
  condition" is accurate. The OutflowBC and ExtrapolationBC improvements are not mentioned.
- **Pre-existing, not caused by these commits:** 1-D Burgers with a shock leaving through `ExtrapolationBC(2)` gives
  NaN by t = 1 on both trees (3 of 4 configurations on new, 4 of 4 on old).
- **Kernels.** The body, its arguments and its count (9) are unchanged. The ghost path writes only `gradients[p]` and
  `particle_orders[p]` of its own particle, so there is no race. KA CPU matches Polyester to 1.3e-15 (`ka_new.out`).
  Streamed/aligned/dynamic paths and limiters read `gradients[j]` as before. Central/Upwind/WENO are unaffected (no
  gather).

## #40: conservation, adaptivity, devices

- `adapt.out`: with or without an estimator, `mass_residual`, the change of `total_mass` and the change of
  `interior_mass` are equal and at round-off (≤ 1.1e-14) for 9 wall-adjacent cases. Before, `total_mass` changed by
  1e-4 to 1.3e-3 per call with an estimator. The interior Σ V stays exactly |Ω| even without an estimator: the remap's
  εV correction acts over the interior only. Interior volumes are never zero in any probe case (minimum 0.11 Δx^D,
  MLS2 jittered), so `Un = mn / Vn` in the remap is safe.
- Float32: interior Σ V = |Ω| within 1.5e-5 for every estimator, box and disc. Discs and 3-D balls: Σ_int V = |Ω| to
  round-off (it was 0.23-0.99).
- Users: HyperCloud.jl (`main_dev` and all branches) never reads volumes, `total_mass` or `interior_mass` except
  `_grid_fingerprint` (a copy) and the GPU MLS-volume runner checks, so its mass statistics are unaffected.
  `Simulations/tools/adapt_study.jl` and several `study/conservation/*.jl` scripts sum `pg.core.volumes` over all
  particles. On bounded grids their numbers now mean the interior content. That is intended, but older stored results
  are not comparable.

## Verdict

#39 is a small, correct change with a large effect. It fixes D1 at the lattice wall, at 0.5 h, on a jittered wall and
for MUSCL5, and it turns the disc acoustics, the OutflowBC channel and the 2-D ExtrapolationBC(2) box from first
order or unstable into convergent runs. The partial MOOD passes stay correct, the kernel is backend-safe, and the
cost is 3-22 % per step, a third of which could be avoided (F2). It also changes MOODu2 at walls (for the better)
without saying so (F3). #40 is correct too: interior volumes sum to |Ω| exactly on every shape, ghosts carry none,
the adaptivity is exact for `total_mass` and `interior_mass` alike, and Float32 is fine. Its documented accuracy
figures and its 2-D quadrature test, however, rest on a harmonic test function, so the claimed orders (3-4 in 2-D)
and Shepard errors are not what a generic function gets (F1). `conservation_defect` near walls changed without
notice (F4).

Earlier findings: D1 **OK** (fixed).
New findings: 1 medium (F1), 3 low (F2, F3, F4); all confirmed.
