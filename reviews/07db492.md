## Findings

### F1 (high, CONFIRMED) — shape domains that are unbounded along an axis cannot be gridded: `domain_volume` ignores `mins`/`maxs`
`src/Grid/Volumes.jl:94-97` calls `shape_volume(geom.shape)`, which integrates over `bounding_box(shape)`
(`Shapes.jl:93-96`) and throws for an unbounded shape, or returns `Inf` for an open `Cuboid`
(`Shapes.jl:200`). The domain's own box (`geom.mins`/`geom.maxs`, required exactly in this case by
`Domains.jl:64-68`) is never used. `ParticleGrid` calls `update_volumes!` → `_renormalise_volumes!` →
`domain_volume` at construction (`ParticleGrids.jl:284`, `Volumes.jl:236`). `probe_unbounded.jl`:
- the docs example "a rotated plate in a periodic channel" (`domains.md`, second code block):
  `ArgumentError: shape_volume: the shape is unbounded` from `ParticleGrid`;
- `GeometricDomain(HalfSpace((0.5, 0), (1, 0)); mins = (0, 0), maxs = (1, 1))` (the case of the test at
  `unit_core.jl:739`, which builds only the domain): same error;
- `GeometricDomain(Cuboid((0,0), (1,1); open = (true, false)); is_periodic = (true, false), mins, maxs)`: the grid
  is built but **every volume is `Inf`** and `interior_mass` is `Inf`.
So every periodic shape domain other than `get_rectangular_domain` (which keeps its analytic `:rectangular` method),
and every shape cut from half spaces, is unusable, although the docstring and the docs describe exactly these
cases.
- Fix: integrate the shape clipped to the domain box (`intersect(shape, Cuboid(geom.mins, geom.maxs))`, or pass the
  box to the lattice integration), and compute it once at construction (see F4). Add a test that builds a
  `ParticleGrid` on the docs' periodic example and on the half-space domain and checks `domain_volume`.

### F2 (medium, CONFIRMED) — `wall_geometry` behind convex corners of an intersection: wrong wall point for obtuse corners, no convergence for acute ones
`src/Grid/Domains.jl:306-323`. The repeated projection is the method of alternating projections onto the pieces.
For half spaces it converges to *a* point of the region's boundary, not to the nearest one, and its rate is
`cos²` of the corner angle; there is no convergence check after the eight steps, the last iterate is used
anyway. `probe_shapes.jl` §3: region `Cuboid((-5,0),(5,5)) ∩ HalfSpace` with interior angle α at the origin,
20 000 ghost positions within 0.3 of the corner, exact distance = distance to the two boundary segments:

| α | max rel. error of the wall distance | samples with error > 1e-6 | mirror image `x − 2dn` of the worst sample |
|:--|:--|:--|:--|
| 15° | **0.76** (0.054 instead of 0.228) | 9259 | **outside**, sd +0.043 |
| 30° | 0.34 | 8449 | **outside**, sd +0.0073 |
| 45° | 0.075 | 7516 | inside |
| 60° | 0.0059 | 6395 | inside |
| 90° | 2e-16 | 0 | inside |
| 120° | **0.15** (0.0985 instead of 0.0860) | 3662 | inside |
| 150° | 0.080 | 1453 | inside |
| 170° | 0.011 | 444 | inside |

Traces (`probe_wedge_dbg.jl`): at 120°, x = (−0.043, −0.0745) (nearest point: the corner) the iteration lands on the
bottom face at (0.0215, 0) after two steps and stops there (a boundary point, but not the nearest; normal
(−0.65, −0.76) instead of (−0.5, −0.87)). At 15° and 45° it is still halving its way to the corner after 8 steps,
so `p` is outside the region and the returned distance is `|x − p|`.
The docstring ("repeating from there until the projection lies on the boundary") and the test comment "Every ghost's
mirror image lies in the region" (`unit_core.jl:726`) only hold for 90° corners, the only ones tested (step corner).
Ramps (15°–30° compression corners give 150°–165° fluid corners), wedges and rotated obstacles produce such corners;
`MirrorBC` evaluates its fit at the mirror image of these ghosts, which for acute corners lies in the ghost band.
(Inside a union, which only affects interior particles, the iteration overestimates too: union of two overlapping
boxes forming `[0,3]×[0,1]`, at (1.5, 0.5) it returns distance −0.707 and normal (0.71, −0.71) instead of −0.5 and
±y. Interior wall data is stored but not read by any condition today.)
- Fix: compute the nearest point properly for the corner case, e.g. Dykstra's projection algorithm (converges to the
  nearest point of an intersection of convex pieces) with a convergence test and a larger iteration cap, or take the
  best of the candidates {projection onto each active piece if it lies on the boundary, the converged corner point};
  if not converged, at least fall back to a point whose mirror image is in the region and document the bound. Add a
  wedge test at 30°/120°/150° (distance vs analytic, mirror image inside).

### F3 (medium, CONFIRMED) — spherical domains are not bitwise identical: lattice points one ulp outside the sphere become interior
`Shapes.jl:214` + `Domains.jl:70`: `sqrt(sum(abs2, x − c)) − r <= 0` replaces the old `sum(abs2, x − c) <= r^2`.
The rounding of the `sqrt` maps squared distances just above `r²` to exactly `r`. `probe_regress.jl`: **18 of 96
spherical grids differ** — all the unjittered ones with centre 0 / radius 1 or centre 0.5 / radius 0.5 (2-D n = 20,
3-D n = 10/14, F64 and F32), e.g. 2-D `get_spherical_domain(Float64, (0,0), 1)`, dx 0.1, R 2.5 dx: N 541 → 545.
`probe_sphere.jl`: 2–24 points per grid flip, every one from ghost to interior, e.g. (0.6000000000000001, −0.8)
(|x| − 1 = +8.9e-17 exactly), F32 (0.8000001, 0.6). BigFloat arithmetic puts **all** flipped points outside: the old
test was the exact one. 1-D intervals are unaffected (0 of 140 cases, `|x|` is exact), and jittered grids did not hit
it in the probe. The commit message and docs claim "the same particles and tags as before".
- Fix: let `Ball` decide inside/outside on the squared distance (e.g. an `_inside(shape, x)` hook defaulting to
  `signed_distance(shape, x) <= 0`, with `Ball` using `sum(abs2, x − c) <= r^2`, used by `is_interior_func` and
  `tag_func`), or accept the change and correct the claim. Add the old rule as a check to the disc test
  (`unit_core.jl:706-713` checks only the wall distances, so it did not catch this).

### F4 (medium, CONFIRMED) — `domain_volume` of a shape domain is a 2 M-sample lattice integration on every call
`Volumes.jl:94-97` → `shape_volume` (`Shapes.jl:93`), not cached. `_renormalise_volumes!` calls it on every
`update_volumes!`, which a moving grid runs after every step (`TimeSteppers.jl:574`), and adaptivity on every event
(`Adaptivity.jl:220`). `probe_volcost.jl`, `update_volumes!(pg, ShepardVolumes())`, median of 5, `-t 2`:

| grid | rectangular 3×1 | step (box − block, CSG) | the same box via CSG |
|:--|:--|:--|:--|
| h = 1/50 (N ≈ 9k) | 0.10 ms | 17.6 ms | 17.5 ms |
| h = 1/100 (N ≈ 33k) | 0.30 ms | 17.7 ms | 17.8 ms |
| h = 1/200 (N ≈ 126k) | 1.15 ms | 18.6 ms | 18.7 ms |

i.e. 15–175× the cost of the volume update, and a fixed ~18 ms per step on a moving grid (more for deeper CSG trees
and in 3-D: 33–49 ms per call in `probe_shapes.jl` §9).
- Fix: compute the volume once in the `GeometricDomain(shape; …)` constructor (a field, or a `volume` keyword so users
  can pass a known value) and return it from `domain_volume`. Together with F1.

### F5 (low, CONFIRMED) — `mins`/`maxs` smaller than the shape silently crop the region
`Domains.jl:64-68` takes `mins`/`maxs` on every axis if given and only checks finiteness and order.
`probe_crop.jl`: `GeometricDomain(Ball((0,0), 1); mins = (0,0), maxs = (1,1))` builds a grid whose interior
particles stop at the canvas edge (69 interior particles at x < 0 down to x = −0.15, no ghosts there, so the cut
carries no boundary condition), while `domain_volume` is π (the whole disc), so all volumes are scaled by ~3.5.
The builder passes `:mins`/`:maxs` whenever present (`Builders/domains.jl:109-110`), and every HyperCloud example
sets `:Grid_mins`/`:Grid_maxs`, so switching an example to `:domain => :shape` keeps a stale box.
- Fix: use `mins`/`maxs` only on axes where the bounding box is infinite (as the docstring says: "along an axis where
  it is unbounded … must be given"), or throw/warn when they do not contain the finite extent of `bounding_box`.

### F6 (low, CONFIRMED) — a tag of 0 (or negative) from `Tagged`/`boundary_tag` turns ghosts into interior particles
`Shapes.jl:342-347`: `Tagged(shape, tag)` and `_retag(f, tag) = Int(f(tag))` accept any integer; `tag_func`
(`Domains.jl:71`) returns it and `get_points` sets `is_boundary = tag != 0`. `probe_shapes.jl` §7:
`GeometricDomain(Tagged(Cuboid((0,0),(1,1)), 0))`, h = 0.1: **156 particles outside the region with
`is_boundary == false`**, i.e. updated by the scheme with no condition. The `Cuboid` guards its own tag with
`max(…, 1)`; user shapes and `Tagged` functions have no guard.
- Fix: check `tag >= 1` in the `Tagged(shape, ::Int)` constructor, and in `tag_func` throw (or clamp with a warning)
  when `boundary_tag` returns < 1 for an outside point.

### F7 (low, CONFIRMED) — builder `:shape`: element-type mismatch only warns, then fails obscurely
`Builders/domains.jl:106` warns when `eltype(shape) != T` and builds the domain in the shape's type anyway;
`ParticleGrid(geom::GeometricDomain{…, D, T}, nominal_dx::NTuple{D, T}, …)` then raises a `MethodError`
(`probe_builder.jl`: a `Ball((0f0, 0f0), 1f0)` in a Float64 run). Also, string shapes are `eval`ed in
`HyperCloudCore` (`:103`), so a user shape type defined in `Main` cannot be named, and the context's `D` is not
checked against `ndims(shape)`. (`eval` of config strings follows the existing `parse_bc` precedent, `:20`.)
- Fix: `error` with a clear message on a type/dimension mismatch (or convert built-in shapes), and evaluate strings in
  `Main` like `parse_bc`'s constructor lookup, or document the restriction.

## Correctness checks that passed

- **Rectangular domains bitwise identical** to 5409209: 1632 grids (1-3-D, F64/F32, offset/anisotropic/thin boxes,
  periodic on each axis and all, anisotropic spacing, jitter up to 0.45 dx, R 2.5/5.5 h): positions, tags,
  `is_boundary`, volumes all equal. On 1.44 M individual points (random, walls, next/prevfloat of the walls, corner
  diagonals, ±Inf, ±floatmax) `is_interior`/`get_tag` agree for every non-periodic box; the tag rule of
  `reviews/9388ad6.md` (face farthest outside, lower tag on ties, periodic faces skipped) is reproduced by
  `_box_face`.
- **Cuboid**: signed distance equal to a brute-force nearest-point distance (F64 0.0 error, F32 ≤ 2.1e-7) in
  1-3-D with and without open axes; unit normals everywhere; open axes give no faces/tags and infinite bounds;
  all-open boxes return −Inf and `wall_geometry` short-circuits on it.
- **Rotated**: 2-D matrix is counter-clockwise; 3-D Rodrigues matrix is the right-handed rotation (`K` is the
  cross-product matrix; z-axis 90° maps x→y; x-axis 90° maps y→z, tag of the rotated y-max face correct);
  random axis/angle/centre: `sd(R y) = sd(y)` and `n(R y) = R n(y)` to 7e-15, `det R = 1`; the rotated bounding box
  contains 10⁵ rotated samples; Float32 stays Float32.
- **CSG**: union outside is exact (nearest piece; L-shaped notch ghosts get the right face, tag and distance);
  intersection inside is exact; box minus disc: ghosts in the hole get the disc's tag, distance and inward-pointing
  normal; the step-corner case of the test (90°) converges to the corner.
- **`shape_volume`**: relative errors 4e-7–2.3e-5 (2-D) and 1.6e-5–3.1e-4 (3-D) on box−step, box−disc, rotated
  box ∩ box, overlapping discs/balls; no allocation; 9–49 ms per call. (The docstring's "below 1e-5 in 2-D" is
  exceeded by the rotated square, 2.3e-5.)
- **Legacy constructor**: same accepted argument types and MethodErrors as before (`probe_legacy.jl`); NaN wall
  geometry; label-dispatched `domain_volume` still used; `GeometricDomain{Val{:Mach3Step}, 2, T}` methods downstream
  still match after the extra type parameter.
- **Type stability / allocations**: interior test, tag and `wall_geometry` on a CSG corner ghost infer
  `Tuple{Bool, Int64, Tuple{SVector{2,Float64}, Float64}}`; 48 bytes in the probe come from the global call site.
  All of this is host-only (no kernel rules apply).
- **Float32** CSG grid (box − disc) builds, tags 1–5, Float32 normals, Σ V = 0.87434 (exact 0.874336).

## Minor issues

- `Shapes.jl:159`: `sqrt(sum(abs2, max.(q, 0)))` underflows for points outside by less than `sqrt(floatmin)`
  (1e-154 F64, ~1e-23 F32): `(-1e-170, 0.5)` and Float32 `-1f-25` are now interior with tag 0 (old: outside). Not
  reachable from lattice/jitter in practice; `m * sqrt(sum(abs2, max.(q, 0) / m))` with `m = maximum(q)` avoids it.
- Periodic boxes: `is_interior`/`get_tag` of points outside a periodic axis only changed from "outside, nearest-plane
  tag" to interior (`probe_points.jl`, ~420 k of the probe points). Library paths wrap first (`Domains.jl:254`,
  `Adaptivity.jl:472-473`), so only user code calling them on unwrapped points sees it; worth a sentence in the docs.
- A closed shape on a periodic axis is accepted silently (docs: "must be open along it"): interior particles at the
  seam get wall distance 0 and the seam normal (`probe_shapes.jl` §8). Only interior data, so harmless today; a check
  in the constructor (`bounding_box` finite on a periodic axis → error) would enforce the documented rule.
- Default tag collisions: `Cuboid(…) - Ball(…)` gives the hole tag 1, the same as the left wall; the docs example uses
  `Tagged`, but a sentence warning about this would help.
- `Rotated` accepts reflections (orthogonality check only, `Shapes.jl:390`); harmless for distances, but the
  docstring says "rotated".
- `tag_func` evaluates the signed distance twice for ghosts and `boundary_tag` of a composite evaluates every child's
  normal (`_probe`); host-only and cheap relative to the rest (see Performance).
- `struct TestParaboloid` is defined inside a `@testset` (`unit_core.jl:666`); fine at top level, but it leaks into
  the test module for the following testsets.

## Verdict

The shape layer is a clean design and its primitives are right: the `Cuboid` distance is exact in 1-3-D with open
axes, `Rotated` follows the stated conventions in 2-D and 3-D, union-outside/intersection-inside are exact, Float32
works, the legacy constructor is unchanged, rectangular grids are bitwise identical to 5409209 on 1632 grids, and
grid construction is only 2–9 % slower. Full suite green. But the advertised uses beyond plain boxes and discs have
gaps: any shape domain that is unbounded along an axis (periodic channels with obstacles, half spaces) fails at
`ParticleGrid` or gets infinite volumes because `domain_volume` ignores the domain box (F1); `wall_geometry` is
wrong behind non-right-angled convex corners (up to 15 % at obtuse corners, non-converged with the mirror image
outside the region at acute ones) (F2); spherical lattice grids differ from before by 2–24 boundary particles (F3);
the volume is re-integrated on every moving-grid step (F4); plus cropping (F5), unchecked tag 0 (F6) and the builder
type mismatch (F7).
Findings: 1 high (F1), 3 medium (F2–F4), 3 low (F5–F7); all confirmed.
